## 0｜模块总览

| 模块 | 职责 |
|---|---|
| **Core** | 游戏运行框架（启动、状态、时间、Tick、全局事件） |
| **Gameplay** | 游戏玩法和玩家交互 |
| **Magic Circuit** | 魔法种子、连接和魔法回路 |
| **Cell** | 环境状态 |
| **Level** | 关卡规则和关卡运行状态 |
| **Presentation** | 游戏状态的视觉表现 |
| **Data** | 静态游戏数据 |

> 注：Cell / Level 在职责上属于 Gameplay 域（「Gameplay 包含 Player、Level 和 Cell」），Magic Circuit 独立成模块；下文按模块分节。

## 1｜Core

Core 是整个游戏的运行基础，负责：游戏启动、游戏状态、时间管理、系统初始化、系统 Tick、全局事件。

包含三部分：**Tick、Event、GameManager**。

### GameManager

- 负责管理整个游戏生命周期：游戏启动、系统初始化、游戏状态切换、游戏结束。
- 游戏状态 `GameState` 枚举：**初始化、加载、游戏中、暂停、胜利、失败**；GameManager 执行这些枚举状态。
- 做一个 **Service 容器**，注册所有的单例管理器。
- GameManager 只负责**协调**整个游戏的生命周期。

### Tick

- 负责驱动需要持续更新的游戏系统，统一管理运行时更新。
- 不同系统可以拥有自己的 Tick 更新频率：例如角色运动需要高频更新，而部分环境模拟可以按照事件驱动方式运行。
- 由 TickManager 提供。

### Event

- 用于不同系统之间进行**低耦合通信**。
- 例：玩家投掷种子 → 产生种子投掷事件 → Magic Circuit 系统接收处理；环境发生变化 → 产生环境变化事件。

## 2｜Gameplay

负责玩家实际体验到的游戏规则，**不负责具体的视觉表现**。

包含 **Player、Level 和 Cell**（Cell / Level 详见 §3 / §5）。

### World / WorldGrid

- **Runtime 有自己的 World Grid**（与编辑器 Tilemap 严格分开，见 §7）。
- WorldManager：大地图，存一个容器装 WorldGrid。
- 每个关卡有自己的 WorldGrid 实例。
- 负责加载、清理、初始化。

### Player

- 组成：`playerInput` + `playerActor`（容器，注册组件）。
- Player 是玩家控制的游戏实体，负责：角色移动、跳跃、投掷魔力种子、玩家资源管理。
- 核心状态：位置、速度、当前运动状态、剩余魔力种子数量。
- 使用 **Unity 2D Physics** 处理角色与环境之间的碰撞。
- **Player 不直接修改 Cell。** 投掷魔力种子时，Player 向 Magic Circuit 系统提交一次**种子投掷请求**；后续的种子落点、连接和魔法效果全部由 Magic Circuit 系统处理。
- （2026-10-08 增补）玩家资源 = 各属性种子的库存数量（截图参考：蓝 ×2、红 ×2、黄 ×4）；种子自带魔法属性（§4 核心规则 2）。

## 3｜Cell

- 组成：`cellActor`（容器 / 预制件）+ `Cell`（动态数据）。
- **Cell 本身是一个字典，存数据**——Cell 不是一个 GameObject，是**纯粹的游戏状态单元**，表示环境中的一个空间位置以及该位置当前的环境状态。
- 字段（原文笔记照录，类型映射待代码化确认）：

| 字段 | 类型（作者笔记） |
|---|---|
| 位置 | 三维向量 |
| 类型 | 枚举 |
| 当前状态 | 枚举 |
| 魔法状态 | 枚举 |
| 连接关系 | 待定 |
| 锁定状态（是否受重力） | 待定 |

- 每个 Cell 有：锁定状态（是不是受到重力）、类型、等等。
- Cell 状态随游戏运行变化，生命周期示例：**正常 → 受魔法影响 → 不稳定 → 塌陷 / 消失**。
- **Cell 本身只描述状态**，不负责播放动画、粒子效果或声音；状态变化由 Presentation 系统负责表现。
- （2026-10-08 增补）**魔法属性**（静态：决定与哪种属性种子反应，截图参考为蓝 / 红 / 黄）与**魔法状态**（运行时：受魔法影响的当前状态）是两个字段；魔法属性取值清单走配置表（§7）。

## 4｜Magic Circuit

- 负责计算 World 的相邻格子，触发；**抛出事件执行**。
- **执行器：操控 World**（魔法效果对环境的修改经由 Magic Circuit 落地）。
- 负责处理：魔力种子、Cell 连接、Circuit 构建、魔法效果。

**核心规则（2026-10-08 拍板定案，不再摇摆）：闭环模型，种子是源节点**

1. **世界默认冻结**：游戏开始时、每次反应结束后，范围内 Cell 无重力、无物理，互相「黏在一起」（锁定态）。推导含义：冻结的方块允许悬空。冻结「范围」走**游戏全局配置**（Data 层数据，2026-10-08 拍板）。
2. **种子自带魔法属性**：玩家丢出的种子本身就是一个带魔法属性（颜色）的格子；**接触格子即触发判定**。扔出即在落点生成一个魔法格子，落定后作为场上节点**持续存在**，可参与后续回路（2026-10-08 拍板）。
3. **连接查表**：落点周围符合条件的 Cell 与种子建立连接、向邻接导通；「符合条件」= 查 Magic 配置表（种子属性 × Cell 魔法属性，见 §7）。
4. **成环 = 回路成立**：连接图上出现**经过种子的闭合回路**才触发魔法效果。
5. **效果查表**：由回路组成（环上 Cell 的魔法属性 / 类型）决定效果（消失 / 塌陷 / 解锁重力，M1 范围）。
6. **解锁 = 物理开启**：被效果解除锁定的 Cell 获得重力与物理效果，开始运动。
7. **重查成环**：环境变化后重查受影响 Cell / Circuit；断边、新邻接可能产生新环 → 新效果（连锁的本质是图重组）。
8. **稳定收敛**：直到无新环、无运动 → 范围内 Cell 重新冻结 → 本轮反应结束。

**核心流程（Simulation 主循环）：**

1. 玩家投掷魔力种子 → 确定种子落点。
2. 检查落点周围符合条件的 Cell，与种子建立连接。
3. 根据当前 Cell 状态和连接关系，计算对应的魔法效果。
4. 魔法效果修改环境状态。
5. 环境变化后，**重新检查受影响的 Cell 和 Circuit**，由此形成连续的环境变化。
6. 连锁反应示例：种子形成 Circuit → 某 Cell 消失 → 原本连接的其他 Cell 失去连接 → 新连接关系产生新 Circuit → 新魔法效果 → …… **直到环境进入稳定状态**。

> Magic Circuit 系统是游戏中**最重要的 Simulation 系统**。

## 5｜Level

- 组成：`LevelManager`（初始化、加载、清理）+ `Level`（配置）。
- Level 负责定义和运行一个具体关卡，**不负责定义底层魔法规则**。
- 关卡提供：初始环境、玩家初始状态、目标、时间限制、资源限制。
- Level 运行时管理当前关卡状态：关卡开始、计时、目标判断、胜利判断、失败判断。
- 关卡设计核心原则：提供初始局面和规则，**不提供唯一解法**——Level 不保存玩家应执行的具体步骤，玩家通过 Magic Circuit 和环境变化自行找到通路。

## 6｜Presentation

- 负责把游戏运行状态转换为玩家看到的画面，**不拥有游戏核心状态**。
- 主要包含：**World、Character、VFX、Camera、Audio、UI**。

| 子系统 | 职责 |
|---|---|
| World | （待补） |
| Character | 动画机。负责 Player 的视觉表现：Sprite、动画、朝向、角色相关特效。**不负责角色运动规则**——Player 决定位置和状态，Character 只负责表现。 |
| VFX | 魔法回路、种子、环境变化等视觉效果。**不参与游戏规则计算。** |
| Camera | 玩家视角，当前使用二维相机。未来增加空间层次时，通过渲染层、景深、前后景、灯光增强空间感，**不改变 Gameplay 的二维逻辑**。 |
| Audio | AudioManager；配表（音频走配置表）。 |
| UI | （2026-10-08 截图参考）种子库存（左下，带数量）、倒计时表盘（右）、重开 R（左上）、魔法手册 TAB（左下）、心 ×3（顶部，语义待确认 §10-#14）、投掷轨迹预览（弧线） |

## 7｜Data & Editor

- Data 保存游戏的**静态设计数据**，与运行时状态**严格分离**。
- 主要包括：Cell 数据、Magic 数据（**种子属性 × Cell 魔法属性 → 连接 / 效果**判定表，即「填表」的对象，2026-10-08）、Level 数据、Player 数据、其他游戏配置。
- 配置方式：**用编辑器编辑，然后保存**。

### Level Editor

- 用于创建和编辑关卡的**初始状态**；编辑的不是运行时 Cell，而是 **Level Data**。
- 编辑器操作 Tilemap 时，同时生成或修改对应的 **Cell Definition**。
- 示例：在坐标 `10, 5` 放一个岩石，编辑器最终保存：

| 字段 | 值 |
|---|---|
| 位置 | 10,5 |
| 类型 | Rock |
| 初始状态 | Normal |
| 锁定 | 是 |
| 重力属性 | Static |
| 魔法属性 | FireReactive |

- **Editor 本身使用 Unity Tilemap**，但必须把「Tilemap 是编辑器工具」和「Cell 是运行时 Simulation 状态」分开：编辑完成后，把 Tilemap 转换成 Level Data；Runtime 有自己的 World Grid。

## 8｜架构铁律（跨模块不变量）

> 逐条有出处，违反任何一条 = 架构违规，Review 直接 FAIL。

1. **Cell 不是 GameObject**，是纯数据状态单元（字典存数据）；`cellActor` 预制件只是表现容器。（§3）
2. **Cell 不播动画 / 粒子 / 声音**，状态表现归 Presentation。（§3）
3. **Player 不直接修改 Cell**，只能向 Magic Circuit 提交种子投掷请求。（§2）
4. **Magic Circuit 是唯一的执行器**：落点判定、连接、魔法效果、修改 World 都由它驱动。（§4）
5. 环境变化后必须**重查受影响的 Cell / Circuit，直到稳定**——连锁收敛是 Simulation 的终止条件。（§4）
6. **Presentation 不拥有核心状态**，VFX / Character 不参与规则计算。（§6）
7. **Data 与运行时状态严格分离**；Tilemap 只是编辑器工具，Runtime 用 World Grid。（§7）
8. **Level 不保存解法步骤**，只提供初始局面 + 底层规则 + 目标。（§5）
9. **世界默认冻结**：无魔法作用时 Cell 无重力无物理；「解锁 = 物理开启」只是反应期间的临时态，反应结束重新冻结。（§4，2026-10-08 拍板）
10. **成环判定**：魔法效果仅由经过种子的闭合回路触发；效果内容由 Magic 配置表决定，不写死在代码。（§4，2026-10-08 拍板）
11. **深度只属于景观**：gameplay 全部 z=0 锁定，z 轴仅供表现层（景深 / 视差）使用，模拟逻辑单层。（§2/§6，2026-10-08 拍板）

## 9｜一次投掷的完整事件流（整理）

```
玩家输入 (playerInput)
  → Player 提交种子投掷请求 [事件: SeedThrown]
    → Magic Circuit: 确定落点
    → 检查周围 Cell → 建立连接 → 构建 Circuit
    → 计算魔法效果 → 执行器修改 World [事件: EnvironmentChanged]
    → Presentation 表现变化（VFX / CellActor / Audio）
    → 重查受影响 Cell / Circuit → 新 Circuit? → 循环
    → 环境稳定 → 本轮结束
Level 计时 / 胜负判断持续运行（GameManager: Playing）
```
